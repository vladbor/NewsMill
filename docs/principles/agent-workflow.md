# Нормы agent-first разработки в этом репозитории

Как автономный агент работает в NewsMill: единый цикл и правила, обязательные
для каждого изменения. Это нормы работы, а не стиль кода — стиль вынесен в
`docs/principles/coding-standards.md`.

## 1. Рабочий цикл агента

1. **Контекст** — прочитать `memory/active-context.md` (над чем работаем сейчас),
   затем `README.md`, релевантные исходники и нужные `docs/`.
2. **План** — кратко изложить план и ожидаемый diff ДО правок кода. Если задача —
   доработка, следовать плану из `docs/execution-plans/`.
3. **Правка** — минимальные точечные изменения в рамках существующей структуры.
4. **Проверка** — `ruff format .`, `ruff check .`, `pytest -v`; ноль warnings.
   Миграции — только сгенерировать, не применять.
5. **Обновление памяти** — после задачи обновить:
   - `memory/progress.md` — сделано / осталось;
   - `memory/active-context.md` — следующий шаг;
   - `memory/decisions.md` — если принималось решение (ADR-стиль);
   - `README.md` / `docs/` — если затронуты контракты, эндпоинты или схема БД.

## 2. Как обращаться с правилами

- Правило, встреченное во второй раз, выносится в `docs/` и не повторяется
  в промпте — в AGENTS.md остаётся только указатель на него.
- Если правило уже есть в AGENTS.md / docs/ — ссылаться на него, а не переписывать.
- `docs/` — стабильное знание о системе; `memory/` — изменчивое состояние работы.
- Стиль кода и конвенции тестирования — `docs/principles/coding-standards.md`.

## 3. Жёсткие запреты (must never)

- Не применять миграции (`alembic upgrade/downgrade/stamp`) — только генерация.
- Не читать, не печатать и не логировать `.env`, секреты, токены, ключи.
- Не редактировать `pyproject.toml` / `uv.lock` без явного запроса.
- Не реорганизовывать структуру каталогов без явного одобрения.
- Не игнорировать линтер без оправданного `# noqa: <rule>`; не использовать
  wildcard-импорты; не хардкодить секреты/конфиг.
- Не коммитить артефакты: `__pycache__/`, `.venv/`, `.ruff_cache/`, `.env`.
- Не коммитить с падающими тестами или warnings.
- Обязательно подтверждать у пользователя изменения README.md и файлов в `docs/`.

## 4. Коммуникация

- Commit-сообщения — на английском, краткие, описательные; один логический коммит.
- Документация в `docs/` — на русском.
- Соблюдение цикла выше — главная метрика качества работы агента.
