# Базовые принципы проекта (core beliefs)

Система приоритетов, из которых следуют все остальные решения в репозитории.

1. **Async по всему стеку**. Оба сервиса — полностью асинхронные (FastAPI +
   FastStream, `httpx`, `aio-pika`, SQLAlchemy async). Никакого блокирующего I/O
   в горячем пути.

2. **Дедупликация до брокера и у БД**. Запись проходит через очередь один раз:
   Monitor фильтрует по `guid`, Worker страхуется `SELECT` по `link` + `UNIQUE`.

3. **Сбой одного сервиса/ленты — не падение всей системы**. Ошибка ленты
   логируется и пропускается; сбой публикации не роняет Monitor; malformed
   сообщение не роняет Worker.

4. **Миграции БД — только вручную**. Агенты генерируют миграции
   (`revision --autogenerate`), но никогда не применяют их: `alembic upgrade`
   — исключительно человеческая операция.

5. **Секреты и конфигурация — только `.env`**. Ничего не хардкодить, `.env`
   не читать и не коммитить; всё через `pydantic-settings`.

6. **Один сервис — одна роль, минимальный набор инструментов**. Monitor —
   только опрос и публикация, Worker — только обработка и персистентность.
   Никаких лишних зависимостей, брокер — один, база — одна.

7. **Docs-driven разработка**. Изменения архитектуры/контрактов обязательно подтверждаются пользователем и фиксируются в `README.md` и `docs/`; агент следует циклу «план → правка → проверка → обновление памяти» (см. `principles/agent-workflow.md`).
